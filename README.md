## a. Problem Statement

Banks run direct marketing (telephone) campaigns to sell term-deposit products to
their clients. Calling every client is expensive and time-consuming, and most
clients say **no**. The goal of this project is to build classification models
that predict, **before** a call is made, whether a client is likely to subscribe
(`yes`) or not (`no`) to a term deposit, based on their demographic, financial
and past-campaign-contact attributes. This lets the bank prioritize clients who
are more likely to convert, improving campaign efficiency.

This is a **binary classification** problem (target column `y`: `yes` / `no`).

---

## b. Dataset Description

- **Name:** Bank Marketing Dataset (Portuguese banking institution direct
  marketing campaigns)
- **Source:** UCI Machine Learning Repository —
  https://archive.ics.uci.edu/dataset/222/bank+marketing
- **Rows (instances):** 41,188 (after de-duplication ~41,176)
- **Columns (raw features):** 20 input features + 1 target (`y`)
  - 10 categorical: `job`, `marital`, `education`, `default`, `housing`,
    `loan`, `contact`, `month`, `day_of_week`, `poutcome`
  - 9 numeric: `age`, `campaign`, `pdays`, `previous`, `emp.var.rate`,
    `cons.price.idx`, `cons.conf.idx`, `euribor3m`, `nr.employed`
  - `duration` (call duration) is **dropped** — it is only known after a call
    ends and leaks the outcome, so it isn't a valid predictor for a real
    "should we call this client" model.
- **Target:** `y` — has the client subscribed to a term deposit? (`yes`/`no`)
- **Class balance:** Imbalanced — roughly 11% `yes`, 89% `no`.
- Minimum feature (12) and minimum instance (500) requirements of the
  assignment are comfortably satisfied (20 raw features, 41k+ rows; after
  one-hot encoding, 52 model input features).

## d. Models Used

All 5 models below were trained on the **same** preprocessed dataset
(one-hot encoded categoricals + standardized numeric features, 80/20

### Observations

| ML Model Name | Observation about model performance |
|---|---|
| Logistic Regression | Very strong baseline — highest precision (0.71) and MCC (0.384) of all 5 models. When it predicts "yes" it is usually right, but recall is low (misses ~75% of actual subscribers) because it can only draw a linear decision boundary and the classes are imbalanced (~11% positives). |
| Decision Tree | Weakest model overall — clearly the lowest AUC (0.63) and MCC (0.242). A single unpruned tree overfits the training data (memorizes noise) and generalizes poorly on this dataset. |
| kNN | Reasonable, middle-of-the-pack performance. Distance-based similarity is diluted by the 52 one-hot-encoded features (curse of dimensionality), so it can't separate the minority class well — recall stays low despite feature scaling. |
| Naive Bayes | Lowest accuracy and precision, but by far the **highest recall** (0.70) — it catches most real subscribers at the cost of many false positives, because it (incorrectly) assumes all features are independent given the class. Useful if the bank cares more about not missing a "yes" than about wasting calls. |
| Random Forest (Ensemble) | Best AUC (0.799) and best F1-score (0.374) — averaging many regularized trees (max_depth=12) gives it the best overall ranking ability and the most balanced precision/recall trade-off, while nearly matching Logistic Regression's accuracy and MCC. |
| **Overall Winner for this dataset** | **Random Forest (Ensemble)** — it has the best AUC and F1-score, and its MCC (0.383) is essentially tied with Logistic Regression's (0.384), making it the most well-rounded model. **Logistic Regression** is a very close second and is a strong choice too if model interpretability and fast inference matter more than a small edge in ranking ability. |

## How to Run Locally

```bash

streamlit run app.py       # launches the app at http://localhost:8501
```

## App Features

- **Dataset upload (CSV):** upload `test_data.csv` (or any CSV with the same
  raw columns, optionally including the true `y` column) from the sidebar.
- **Model selection dropdown:** choose between Logistic Regression, Decision
  Tree, kNN, Naive Bayes, and Random Forest.
- **Evaluation metrics display:** Accuracy, AUC, Precision, Recall, F1, MCC
  computed live on the uploaded data (when the `y` column is present).
- **Confusion matrix & classification report:** rendered for the selected
  model on the uploaded data.
- A **Model Comparison** tab shows all 6 metrics for all 5 models side by
  side, with a bar chart.
